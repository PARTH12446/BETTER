Prefix Sum — from recognition to mastery

The prefix sum pattern is about precomputing cumulative totals to answer range queries in O(1) time. The skill is recognizing when repeated sum calculations can be replaced with a single precomputed array.

⏱ O(n) preprocessing, O(1) queries
💾 O(n) extra space
15 problems
01

What problem does this actually solve?

A brute-force approach computes the sum of a range by looping through it — that's O(n) per query. Prefix sum precomputes cumulative sums once, then answers any range sum query in O(1) time.

The key insight is that the sum of any subarray can be derived from two prefix sums:

  • Prefix sum array: prefix[i] = arr[0] + arr[1] + ... + arr[i]
  • Range sum: sum(i, j) = prefix[j] - prefix[i-1] (with prefix[-1] = 0)
  • This turns O(n) range queries into O(1) after a single O(n) precomputation.
The one question that decides everything: do you need to answer many range sum queries on a static array? If yes, prefix sum is your tool.

Core Pattern

Range Sum Queries

Precompute prefix sums to answer any range sum in O(1).

  • Preprocess: prefix[i] = prefix[i-1] + arr[i]
  • Query: sum(i,j) = prefix[j] - prefix[i-1]
  • Edge: prefix[-1] = 0 for i = 0
  • Classic: Range Sum Query — Immutable
Extended Pattern

Subarray Counting

Use prefix sums with a hashmap to count subarrays with a given property.

  • Key idea: prefix[j] - prefix[i-1] = k
  • Transform: prefix[i-1] = prefix[j] - k
  • Count: maintain frequency of prefix sums seen so far
  • Classic: Subarray Sum Equals K
Common pitfall

Off-by-one in range sum

The formula changes depending on whether you include the start index.

  • Wrong: prefix[j] - prefix[i] (excludes arr[i])
  • Right: prefix[j] - prefix[i-1] (includes arr[i])
  • Always initialize prefix[-1] = 0 conceptually
  • Or use 1-indexed prefix array to simplify

05

Mistakes that show up across almost every problem

If your prefix sum solution is wrong, it's very likely one of these three things.

Off-by-one in range sum formula

Using prefix[j] - prefix[i] instead of prefix[j] - prefix[i-1] when i > 0. This excludes the element at index i from the sum.

Fix: use 1-indexed prefix array where prefix[0] = 0, then sum(i,j) = prefix[j+1] - prefix[i].
Forgetting to initialize hashmap with 0

In subarray counting problems, the empty prefix sum (0) needs to be in the hashmap before processing. Without it, you'll miss subarrays starting at index 0.

Fix: always initialize map = {0: 1} before iterating.
Using prefix sum when array changes

Prefix sum is for static arrays. If the array is updated frequently, prefix sum preprocessing is wasted — you'd need a Fenwick tree or segment tree instead.

Fix: if the problem has updates, consider a Fenwick tree (BIT) or segment tree instead.
