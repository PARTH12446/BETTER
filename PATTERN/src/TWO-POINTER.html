Two Pointer — from recognition to mastery

Two pointer isn't one trick, it's three related ones. The whole skill is recognizing which of the three a problem wants — this page is built around watching all three run, not just reading about them.

⏱ O(n) time, most cases
💾 O(1) extra space

01

What problem does this actually solve?

A brute-force approach checks every pair of elements — that's O(n²). Two pointer replaces the inner loop with a second index that moves based on information you already have, so each element is visited a constant number of times.

The three variants differ in where the pointers start and what makes them move:

  • Opposite ends — one pointer starts at index 0, the other at the last index. They move toward each other until they meet. Requires the array to be sorted, or at least orderable by the property you're comparing.
  • Fast & slow — both pointers start at index 0, moving the same direction. The slow pointer marks "where the next valid element goes"; fast does all the scanning.
  • Sliding window — both pointers start at index 0. The right pointer expands the window; the left pointer shrinks it when a constraint is broken. The window's size changes dynamically.
The one question that decides everything: is the array sorted (or can you sort it) and are you looking for a pair? → opposite ends. Are you compacting/filtering in place? → fast & slow. Are you looking for a contiguous run that satisfies a condition? → sliding window.

Pattern 01

Opposite Ends

Two pointers converge from both ends of a sorted structure.

  • Move L when: the current result is too small
  • Move R when: the current result is too large
  • Stop when: L crosses or meets R
  • Loop guard: while (L < R)
Pattern 02

Fast & Slow

Both pointers start together and move the same direction at different rates of "commitment."

  • Fast's job: scan every element, decide if it's valid
  • Slow's job: mark where the next valid element gets written
  • Invariant: everything left of slow is already "finished"
  • Loop guard: for fast in range(n)
Pattern 03

Sliding Window

A window of variable size slides across the array, growing and shrinking.

  • Expand: always move R forward, add its element to window state
  • Shrink: while the constraint is violated, move L forward, remove its element
  • Record: update the answer once the window is valid
  • Loop guard: outer for R, inner while for L

05

Mistakes that show up across almost every problem

If your two-pointer solution is wrong, it's very likely one of these four things, in roughly this order of likelihood.

Wrong loop condition: <= instead of <

For opposite ends, using L <= R lets the pointers cross or compare an element against itself, which silently corrupts results in palindrome and pair-sum problems.

Fix: while (L < R) unless you have a specific reason to include L === R.
Shrinking the window with `if` instead of `while`

In sliding window, a single if only shrinks once per expansion. If one new element can violate the constraint by more than one unit, the window stays invalid.

Fix: shrink inside a while loop that keeps running until the constraint holds again.
Confusing "slow" with the current fast index

In fast & slow, forgetting that slow only advances when a valid element is found means you overwrite good data or leave gaps in the compacted array.

Fix: advance slow only after writing — never advance it just because fast moved.
Not skipping duplicates in problems like 3Sum

Sorting brings duplicates next to each other, but forgetting to skip repeated values for both the fixed index and L/R produces duplicate triplets in the answer.

Fix: after finding a match, advance L and R past any value equal to the one just used.
