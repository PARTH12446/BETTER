The 5 Fundamental Sorts

Each algorithm has a different trade-off between speed, space, stability, and simplicity. Understanding these trade-offs is the key to choosing the right one.

Bubble Sort O(n²)
Idea: Repeatedly swap adjacent elements if they are in the wrong order. Largest "bubbles up" each pass.
  • Traverse from index 0 to n-1
  • Swap if arr[i] > arr[i+1]
  • After each pass, largest is at the end
  • Repeat for remaining unsorted portion

Average
O(n²)

Space
O(1)
Best: [1,2,3,4,5] · Worst: [5,4,3,2,1]
→ [5,4,3,2,1] → [4,3,2,1,5] → [3,2,1,4,5] → ...
Pitfall: Forgetting the optimization flag — without it, sorted arrays still run O(n²).
Selection Sort O(n²)
Idea: Find the minimum element and move it to the correct position. Select the smallest remaining each pass.
  • For each position i from 0 to n-1
  • Find the minimum from i+1 to n-1
  • Swap it with arr[i]
Best
O(n²)
Average
O(n²)
Worst
O(n²)
Space
O(1)
All inputs take the same number of comparisons.
→ [5,4,3,2,1] → find min(1) → [1,4,3,2,5] → ...
Pitfall: Forgetting to find the index of the minimum — you need the position to swap.
Insertion Sort O(n²)
Idea: Build sorted array one item at a time by inserting each element into the correct position.
  • Assume arr[0] is sorted
  • Take arr[i] (starting from i=1)
  • Insert it into sorted left part by shifting larger elements right

Pitfall: Shifting from left to right instead of right to left — overwrites data.
Merge Sort O(n log n)
Idea: Divide and conquer. Divide the array into halves, sort each part, merge them back.
  • Divide array into halves until 1 element each
  • Merge two sorted arrays back by comparing elements
  • Continue merging until full array is sorted

Pitfall: Forgetting to copy the merged result back into the original array.
Quick Sort O(n log n)
Idea: Pick a pivot, partition so left < pivot < right, then recurse.
  • Choose a pivot (middle, last, or random)
  • Partition array so left < pivot and right > pivot
  • Recursively apply to left and right subarrays

When to Use What?

The right sorting algorithm depends on your data size, structure, and requirements.

Small input, mostly sorted
→ Insertion Sort — best for nearly sorted data
Guaranteed O(n log n) time
→ Merge Sort — consistent performance
Average-case fast, in-place
→ Quick Sort — fastest in practice
Just learning / educational
→ Bubble Sort — easiest to understand
Need stable sort
→ Merge Sort or Insertion Sort
Memory-constrained
→ Quick Sort, Bubble, Selection, Insertion (all O(1) space)
04

Common Mistakes

If your sorting implementation is wrong, it's almost always one of these things.

Bubble Sort — No optimization flag

Without the swapped flag, Bubble Sort always runs O(n²) even on sorted input.

Fix: Track if any swaps occurred — if none, break early.
Selection Sort — Wrong minimum index

Finding the minimum value instead of the index — you need the position to swap.

Fix: Track minIndex, not minValue.
Insertion Sort — Wrong shift direction

Shifting from left to right overwrites data — you must shift from right to left.

Fix: Start from the current position and move backwards.
Merge Sort — Forgetting to copy back

After merging, you must copy the sorted result back into the original array.

Fix: Always copy from the temporary array back to the original.
Quick Sort — Bad pivot choice

Always picking first/last pivot causes O(n²) on sorted data.

Fix: Use random pivot or median-of-three.
Not handling edge cases

Empty arrays, single elements, or all equal elements can break sorting implementations.

Fix: Test edge cases — they should return immediately or handle gracefully.
