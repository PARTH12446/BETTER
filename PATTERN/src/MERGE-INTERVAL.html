Merge Intervals — from recognition to mastery

The merge intervals pattern is about processing ranges that overlap. The skill is knowing when to sort, how to merge, and recognizing interval-based problems across different domains.

01

What problem does this actually solve?

A brute-force approach compares every pair of intervals — that's O(n²). The merge intervals pattern sorts intervals by start time and then makes a single pass to merge overlapping ones, achieving O(n log n).

The key steps are:

  • Sort: Sort intervals by their start time (and optionally end time).
  • Iterate: Process each interval in order, comparing it with the last merged interval.
  • Merge: If they overlap (current.start ≤ last.end), update the end to max(last.end, current.end).
  • Add: If they don't overlap, add the current interval as a new merged interval.
The one question that decides everything: are you given intervals (ranges) and need to combine, find overlaps, or detect gaps? If yes, this pattern is your tool.

Core Pattern

Standard Merge

Merge all overlapping intervals into one.

  • Step 1: Sort by start time
  • Step 2: Initialize result with first interval
  • Step 3: If current.start ≤ last.end, merge (update end)
  • Step 4: Else, add as new interval
Extended Pattern

Interval Intersection

Find overlaps between two sets of intervals.

  • Step 1: Use two pointers (i for A, j for B)
  • Step 2: Find overlap: start = max(A[i].start, B[j].start)
  • Step 3: If start ≤ min(A[i].end, B[j].end), add overlap
  • Step 4: Move pointer of interval that ends first
Common pitfall

Wrong merge condition

Using < instead of ≤ for overlapping intervals.

  • Wrong: if (current.start < last.end) — misses adjacent intervals
  • Right: if (current.start ≤ last.end) — includes touching intervals
  • Adjacent intervals [1,2] and [2,3] should merge to [1,3]
  • Always use ≤ for the overlap condition

05

Mistakes that show up across almost every problem

If your merge intervals solution is wrong, it's very likely one of these three things.

Wrong merge condition: using < instead of ≤

Adjacent intervals [1,2] and [2,3] should be merged into [1,3]. Using < would treat them as separate, missing the overlap at the boundary.

Fix: always use current.start ≤ last.end to merge overlapping or adjacent intervals.
Forgetting to sort by start time

If intervals are not sorted by start time, you can't make a single pass to merge them. Overlaps can only be detected after sorting.

Fix: always sort by start time first. If two intervals have the same start, sort by end time as well.
Not updating the end correctly during merge

When merging, you need to take max(current.end, last.end). Some people incorrectly use last.end = current.end, which can shrink the merged interval.

Fix: update with last.end = max(last.end, current.end) to keep the larger range.
