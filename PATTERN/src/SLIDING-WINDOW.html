Sliding Window — from recognition to mastery

The sliding window pattern is about maintaining a contiguous segment that moves through the data. The skill is knowing whether the window should be fixed-size or variable-size — this page shows both running, not just reading.

⏱ O(n) time, most cases
💾 O(1) or O(k) space

01

What problem does this actually solve?

A brute-force approach recomputes the property for every subarray from scratch — that's O(n²). Sliding window updates the result incrementally as the window moves, so each element is added and removed at most once.

The two variants differ in how the window size changes:

  • Fixed-size window — the window size is known in advance (e.g., k). You initialize the window, then slide it one step at a time: remove the leftmost, add the new rightmost.
  • Variable-size window — the window grows and shrinks dynamically. The right pointer expands the window; the left pointer shrinks it when a constraint is violated.
The one question that decides everything: is the window size fixed (given as k) or do you need to find the optimal size (longest/shortest that satisfies a condition)?

Type 01

Fixed-Size Window

Window size is known (k). Slide it one element at a time.

  • Initialize: compute result for first k elements
  • Slide: remove nums[i], add nums[i+k]
  • Update: track max/min/count for each position
  • Loop guard: for i in range(k, n)
Type 02

Variable-Size Window

Window size changes dynamically based on a condition.

  • Expand: move R forward, add its element to window state
  • Shrink: while constraint is violated, move L forward, remove its element
  • Record: update answer once the window is valid
  • Loop guard: outer for R, inner while for L
Common pitfall

Shrink with `while`, not `if`

One new element can violate the constraint by more than one unit.

  • Wrong: if condition: shrink once
  • Right: while condition: shrink repeatedly
  • Always shrink in a while loop until the constraint holds again
  • This is the single most common bug in variable-size sliding window

05

Mistakes that show up across almost every problem

If your sliding window solution is wrong, it's very likely one of these three things, in roughly this order of likelihood.

Shrinking with `if` instead of `while`

In variable-size window, a single if only shrinks once per expansion. If one new element can violate the constraint by more than one unit, the window stays invalid.

Fix: shrink inside a while loop that keeps running until the constraint holds again.
Forgetting to update the answer after shrinking

In variable-size problems, the window may become valid only after shrinking. If you update the answer before the inner while loop, you might record an invalid window.

Fix: update the answer after the inner while loop, when the window is guaranteed to be valid.
Wrong initialization in fixed-size window

When sliding, you need to remove the element that's leaving the window before adding the new one, or add before remove — the order matters for the running sum/product.

Fix: consistent order — either remove then add or add then remove, but don't mix them.
