Fast & Slow Pointers — Floyd's Tortoise and Hare

Two pointers move through the same structure at different speeds. If the structure loops back on itself, the faster one eventually laps the slower one — that meeting is the entire trick. No hashmap, no extra memory, just a speed difference.

⏱ O(n) time
💾 O(1) space
slow +1 step
fast +2 steps

01

Why speed difference detects a cycle

This is not the same "fast & slow" as array compaction problems — there, slow marks a write position. Here, both pointers genuinely traverse the structure, just at different rates. That's what makes a loop detectable.

Picture a circular running track. If two runners start at the same point and one runs twice as fast, the faster runner will eventually lap the slower one — they must meet again, because the gap between them shrinks by exactly 1 step every round.

  • If the structure is linear (no cycle), fast simply reaches the end first — fast == null — and slow never catches up to anything.
  • If the structure loops, fast enters the loop, slow enters the loop, and because fast gains on slow by 1 position per step inside the loop, they are guaranteed to land on the same node within one full loop length.
  • Once they meet, you know a cycle exists — but not where it starts. That needs a second phase (see step 4 below).
Why this works with O(1) space: a hashmap-based cycle check stores every visited node — O(n) space. Fast & slow needs only two pointers, because the meeting point itself is the signal, not a lookup.

02

How to recognize when this pattern applies

Four signals, and you rarely need more than one to be confident.

Repetition

You're repeatedly transforming or traversing values — linked list traversal, or a number chain like digit-square-sum.

Cycle possibility

The structure or transformation could loop back on itself — a cycle in a linked list, or a repeating number sequence.

Need for a midpoint

You need the middle element in a single pass, without knowing the length ahead of time.

O(1) space required

The problem explicitly rules out extra memory — fast & slow uses none beyond the two pointers.

03

Applying the pattern

1

Initialize both pointers at the start.

slow = head;
fast = head;
2

Traverse — move slow one step, fast two, and stop the moment fast can't take a full 2-step move.

while (fast != null && fast.next != null) {
  slow = slow.next;
  fast = fast.next.next;
}
3

Check the meeting point after each move (not just at the end).

If slow == fast at any point → a cycle exists. If fast or fast.next hits null first → no cycle, list simply ends.

4

Add goal-specific logic on top of the base traversal:

• Cycle start: once slow and fast meet, reset slow to head and move both 1 step at a time — they meet again exactly at the cycle's entry node.
• Middle: when the loop ends, slow is sitting on the middle node.
• Number transformations (e.g. Happy Number): treat "apply the transform function" as the "next" movement — everything else is identical.

07

Mistakes that show up again and again

Checking only `fast != null`

You also need fast.next != null in the loop condition — otherwise fast.next.next throws when fast lands on the last node.

Fix: while (fast != null && fast.next != null), always both.
Resetting the wrong pointer to find the cycle start

After slow and fast meet, people sometimes reset fast to head instead of slow, or move both 2 steps instead of 1 in phase two.

Fix: reset slow to head, keep fast at the meeting point, move both by 1 step until they meet again.
Off-by-one on "middle" for even-length lists

A 4-node list has two valid "middles" — which one you land on depends on whether you check fast.next or fast.next.next in the loop guard.

Fix: know which convention the problem wants (lower vs. upper middle) and match your loop condition to it.
Forgetting the transform can immediately cycle to itself

In Happy Number and similar problems, some inputs reach a fixed point (like 1 → 1) rather than a longer loop — treat that as a valid (length-1) cycle, not a bug.

Fix: don't special-case "no change" — let the same slow/fast logic catch it naturally.
