What is a Linked List?

A Linked List is a linear data structure where each element (node) contains data and a reference (pointer) to the next node in the sequence. Unlike arrays, elements are not stored in contiguous memory locations.

Basic Structure
class ListNode { int val; ListNode next; ListNode(int val) { this.val = val; } }
Dynamic size O(1) insert at head O(n) access
Types of Linked Lists
  • Singly — Each node points to next only
  • Doubly — Points to next AND previous
  • Circular — Last node points back to head
02

Linked List vs Array — When to Use What?

Understanding the trade-offs helps you choose the right data structure for the problem.

Use Linked List When
  • Frequent insertions/deletions at beginning
  • Size is unknown/dynamic
  • Memory is fragmented
  • No need for random access
  • Implementing stacks/queues
Use Array When
  • Frequent random access (by index)
  • Size is fixed/known
  • Need cache-friendly access
  • Need O(1) access by index
  • Implementing dynamic arrays

The 5 Core Patterns of Linked List

Master these five patterns and you can solve 90% of linked list problems.

Fast & Slow Two Pointers
Two pointers move at different speeds — one fast (2x), one slow (1x).
ListNode slow = head, fast = head; while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; } // slow is at the middle
Use for: Finding middle, cycle detection, nth from end
Reverse Iterative
Reverse the links between nodes by tracking prev, curr, next.
ListNode prev = null, curr = head; while (curr != null) { ListNode next = curr.next; curr.next = prev; prev = curr; curr = next; } // prev is the new head
Use for: Reversing order, palindrome checking, reorder
Dummy Node Sentinel
A dummy node before head simplifies edge cases (deleting head).
ListNode dummy = new ListNode(0); dummy.next = head; ListNode prev = dummy; // Now safely handle head operations
Use for: Merging, deleting, adding at head, edge cases
Floyd's Cycle Tortoise & Hare
Fast moves 2 steps, slow moves 1 step — they meet if there's a cycle.
ListNode slow = head, fast = head; while (fast != null && fast.next != null) { slow = slow.next; fast = fast.next.next; if (slow == fast) return true; } return false;
Use for: Detecting cycles, finding cycle start
Merge Two Sorted Lists
Compare heads, append smaller, move pointer forward.
ListNode dummy = new ListNode(0), tail = dummy; while (l1 != null && l2 != null) { if (l1.val < l2.val) { tail.next = l1; l1 = l1.next; } else { tail.next = l2; l2 = l2.next; } tail = tail.next; } tail.next = (l1 != null) ? l1 : l2;
Use for: Combining sorted lists, merge sort on LL

How to Recognize Linked List Patterns

These clues in problem statements should immediately make you think of a specific pattern.

"Find middle"→ Fast & Slow pointers
"Detect cycle"→ Floyd's cycle detection
"Reverse"→ Iterative reversal with prev/curr
"Remove nth from end"→ Fast & Slow with distance n
"Merge sorted lists"→ Dummy node + two pointers
"Palindrome"→ Find middle + reverse half
"Intersection"→ Two pointers with length adjustment
"Remove duplicates"→ Single pass with prev and curr

Common Mistakes

If your linked list solution is wrong, it's almost always one of these things.

Losing reference to head

When you move a pointer, you lose the original head reference and can't return the list.

Fix: Always keep a head reference or use a dummy node.
Not handling null pointers

Accessing `node.next` when `node` is null causes a NullPointerException.

Fix: Check node != null before accessing `node.next`.
Infinite loops in reversal

Not storing `next` before changing `curr.next` causes you to lose the rest of the list.

Fix: Store next = curr.next before modifying `curr.next`.
Forgetting to update tail

When merging or adding, forgetting to move the tail pointer forward.

Fix: Always move the tail pointer after appending a node.
Cycle detection off-by-one

Checking only `fast.next != null` without checking `fast != null` can cause errors.

Fix: Check fast != null && fast.next != null.
Not handling empty list

Many solutions fail when `head == null`.

Fix: Always handle the empty list edge case first.
